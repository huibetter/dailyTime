# DailyTime 整体优化阶段四：备份、恢复与数据安全计划

## 阶段目标

为单机本地数据建立可迁移、可校验、失败可回滚的备份恢复闭环。首版采用版本化 JSON 容器，扩展名为 `.dailytime`；不在本阶段引入云同步和账号系统。

## 实施范围

- 定义备份格式版本、应用版本、创建时间和工作区快照。
- 导出项目、文档、标签、设置和附件元数据。
- 支持浏览器/桌面端导出文件和选择文件导入。
- 导入前完成格式、版本和字段校验，不合格文件不修改当前数据。
- 导入采用“作为新工作区恢复”的安全策略，当前版本先提供覆盖当前内存工作区的确认流程。
- 增加空工作区、损坏文件、重复 ID、错误格式和大文件边界测试。

## 验收标准

- 导出的 `.dailytime` 文件可被重新解析并恢复完整业务快照。
- 无效 JSON、未知格式版本和缺失必需字段会显示可读错误。
- 导入失败时当前工作区和设置保持不变。
- 用户明确确认后才会替换当前工作区。
- `npm run typecheck`、`npm run test`、隔离构建和格式检查通过。
- 阶段完成后更新 `docs/history/` 并创建本地 Git 提交。

## 提交拆分

1. `docs: 制定整体优化阶段四备份恢复计划`
2. `feat: 增加版本化 dailytime 备份格式`
3. `feat: 接入设置页备份导入导出`
4. `test: 补齐备份校验和失败恢复用例`

## 后续扩展

- 附件真实文件复制到应用数据目录。
- 密码派生密钥和认证加密。
- 导入到新工作区、原子替换和跨设备恢复。
- 数据库快照与附件包的二进制容器。
