# DailyTime 桌面应用技术框架方案

## Summary

DailyTime 以个人本地工作台为首要定位，保留当前 React/Vite 原型的主要界面和交互，分阶段演进为可安装的跨平台桌面应用。

- 桌面壳：Tauri 2。
- 前端：React + Vite；新模块使用 TypeScript，现有 JSX 按功能逐步迁移。
- 本地数据：SQLite，应用启动后不再把业务数据作为 `localStorage` 的长期存储来源。
- 附件：复制到应用数据目录，数据库只保存相对路径和元数据。
- 备份：单个 `.dailytime` 文件，可选密码加密。
- 首个发布目标：Windows 10/11 x64；Linux 与 macOS 保留构建兼容性，后续单独验证。

## Key Changes

### 1. 应用分层

- `src/` 负责页面、交互和视图状态，不直接访问 SQLite、文件系统或 Tauri API。
- 新增数据访问层，以 repository 形式提供项目、文档、标签、排期、附件和设置的 CRUD 接口。
- 新增桌面桥接层，集中封装 Tauri 命令、文件选择、应用目录、备份导入导出和窗口能力。
- Rust 侧只承载本地能力、数据库迁移、文件操作、备份打包/解包和加密，不承载页面业务规则。
- 使用数据库迁移版本管理表结构；所有写操作通过事务完成，应用退出或异常时不依赖内存状态恢复数据。

### 2. 首版数据模型

首版保留当前核心概念：工作空间、项目、项目文档、标签、文档标签关联、附件和应用设置。

- 文档继续以 Markdown 原文保存，包含标题、正文、状态、计划日期、计划时间和更新时间。
- 排期视图从文档的计划字段查询生成，不额外复制一份日程数据，避免文档与排期不一致。
- 标签独立建表，通过关联表绑定文档；项目删除、文档删除和附件删除必须定义级联清理行为。
- 用户体系改为本机配置：保存显示名、当前工作空间和界面偏好；移除当前 Demo 的登录、退出登录和模拟切换用户逻辑。
- 不为首版引入服务端账号、权限、评论、多人协作或云端同步接口。

### 3. 附件与 Markdown 图片

- 用户上传的附件复制到应用数据目录下的 DailyTime 专属目录，并使用内部唯一名称，避免同名覆盖。
- 数据库保存原始文件名、相对路径、MIME 类型、大小和创建时间。
- Markdown 粘贴图片统一转为应用内附件引用；预览时通过受控的本地资源访问方式加载，禁止把任意路径直接注入页面。
- 导出时将数据库和附件一并写入备份包；导入时先写入临时目录，校验成功后再原子替换或创建新工作空间。

### 4. `.dailytime` 备份格式

`.dailytime` 采用单文件容器格式，内部包含版本清单、SQLite 数据库和附件目录。清单至少记录格式版本、应用版本、创建时间和工作空间标识。

- 无密码时，直接保存可校验的容器内容。
- 设置密码时，使用密码派生密钥后对整个备份载荷进行认证加密；错误密码或校验失败不得修改当前数据。
- 导入前必须明确选择“覆盖当前工作区”或“作为新工作区导入”，默认不自动覆盖。
- 导入失败保留当前工作区不变，并向用户展示可读错误；不得留下半成品附件或数据库。
- 首版不做浏览器 `localStorage` 自动迁移，桌面版首次启动使用新的 SQLite 工作区。

## Delivery Stages

### 阶段 0：桌面壳与工程基线

- 初始化 Tauri 2 配置、Rust 工程和前端开发/构建脚本。
- 保证 React 页面能在 Tauri 开发窗口运行，并能产出 Windows x64 安装包。
- 建立 `src/` 前端层、桌面桥接层和 Rust 命令层的目录边界。
- 新增 TypeScript 编译检查、统一环境变量约定和桌面开发说明。

验收：应用可在 Windows 10/11 x64 启动、关闭、重新打开；现有主要页面可正常渲染；构建产物可安装。

### 阶段 1：SQLite 与本地文件存储

- 建立数据库初始化和迁移机制。
- 将项目、文档、标签、排期字段和应用设置迁移到 repository。
- 增加附件目录管理和数据库记录，替换当前业务数据对 `localStorage` 的依赖。
- 保留必要的界面偏好持久化，但通过统一设置接口读写。

验收：创建、编辑、删除、重启恢复、搜索、标签管理和排期查看均基于 SQLite 工作；异常关闭后不出现半条记录。

### 阶段 2：核心工作流工程化

- 在不改变当前主要交互的前提下拆分页面和状态管理，优先迁移数据类型与公共组件到 TypeScript。
- 使用成熟 Markdown 解析器替换当前手写解析逻辑，并对 HTML/本地资源渲染做安全限制。
- 完善文档标题、正文、状态、计划日期/时间、标签、附件和完成状态的编辑闭环。
- 增加空状态、错误状态、保存中/保存失败状态和基础键盘操作。

验收：核心操作在无网络环境下可完成；刷新或重启不丢数据；预览内容与编辑内容一致；危险操作有确认和失败反馈。

### 阶段 3：备份、恢复与数据安全

- 实现 `.dailytime` 导出、导入、覆盖当前工作区和创建新工作区。
- 增加可选密码加密、密码错误处理、格式版本校验和导入前预检。
- 对数据库、附件和备份包执行完整性测试，覆盖大附件、同名附件、空工作区和损坏文件。

验收：导出的备份可在另一台 Windows 设备恢复；加密备份无密码不可读取；导入失败不改变当前数据。

### 阶段 4：发布与跨平台准备

- 首先固定 Windows 10/11 x64 的本地可重复构建和手动发布流程。
- 为 Linux x64、macOS Intel 和 Apple Silicon 保留 Tauri 构建配置及平台差异清单。
- 首版不做自动更新；版本号、数据库迁移版本和备份格式版本独立管理。
- 建立安装、升级、卸载、数据目录保留和备份恢复的发布检查表。

验收：Windows 安装包可重复构建；升级后数据和附件可用；卸载行为符合预期；跨平台构建阻塞项有明确记录。

## Test Plan

- 单元测试：日期排序、项目/文档/标签 repository、数据库迁移、附件命名、备份清单和加解密。
- 集成测试：创建文档到排期展示、编辑后重启恢复、上传附件后预览、删除后的级联清理、备份导入恢复。
- 回归测试：搜索、项目切换、总项目排期、当前项目排期、响应式布局和现有快捷操作。
- 安装测试：全新安装、覆盖安装、卸载后数据策略、无网络启动、权限不足和磁盘空间不足。
- 发布门槛：`npm run build`、TypeScript 检查、Rust 检查、自动化测试通过后才生成安装包；任何数据迁移或备份失败都视为阻断问题。

## Assumptions

- 首版是单机个人应用，不承诺跨设备同步和多人协作。
- 首版不迁移当前浏览器 Demo 的 `localStorage` 数据，现有 Demo 内容仅作为交互与数据结构参考。
- 首版使用 Windows 10/11 x64 作为实际发布和验收平台；Linux/macOS 先保持架构兼容，待对应平台环境可用后测试。
- 首版提供可选密码加密备份，但不提供密码找回；忘记密码时只能使用未加密备份或重新开始工作区。
- 备份采用“覆盖当前工作区”或“作为新工作区导入”，不做记录级自动合并。
- 首版不接入真实账号、云服务、自动更新、系统托盘、移动端和后台常驻能力。
