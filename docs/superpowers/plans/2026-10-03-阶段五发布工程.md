# DailyTime 整体优化阶段五：发布工程与跨平台验证计划

## 阶段目标

建立可重复、可检查、可追踪的质量与发布流水线，使每个提交先通过质量门禁，版本标签再生成平台安装包。

## 实施范围

- 增加统一 `npm run check` 质量入口。
- 将格式检查范围收敛到项目维护的源码、配置和工作流文件。
- 增加 Rust `fmt`、`check` 和 `clippy` 检查脚本。
- 增加 PR 质量流水线，覆盖前端测试、构建和 Rust 检查。
- 增加 tag 触发的 Windows、Linux、macOS 构建矩阵。
- 增加发布产物清单、构建版本一致性和安装包验证说明。

## 验收标准

- 本地 `npm run check` 可一次完成格式、类型、测试和隔离构建。
- GitHub Actions 的 PR 质量检查不生成发布包，失败时阻止合并。
- `v*` 标签可以按平台生成对应安装包并上传 artifact。
- package、Tauri、Cargo 三处版本号不一致时检查失败。
- 阶段完成后更新 `docs/history/` 并创建本地 Git 提交。

## 提交拆分

1. `docs: 制定整体优化阶段五发布工程计划`
2. `chore: 增加统一质量与版本检查脚本`
3. `ci: 增加 PR 质量门禁和跨平台构建矩阵`
4. `docs: 完善发布与安装验证清单`

## 暂不处理

- 自动更新服务端和签名证书托管。
- 发布说明自动生成和远程制品仓库上传。
- 各平台真实设备上的人工 UI 验收自动化。
